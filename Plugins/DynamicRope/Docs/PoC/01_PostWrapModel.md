# PoC 설계 노트 ① — 감긴 이후(Post-Wrap) 동작 모델

> 상태: Draft (PoC 단계) · 대상: DynamicRope 플러그인
> 목적: 기획서(Notion)의 빈칸인 "로프가 감긴 **이후**(유지/당김/풀림)" 동작을 PoC가 검증 가능한 수준으로 정의한다.
> 이 문서가 스파이크 **S2(움직이는 팔 감김)의 GO/NO-GO 기준**을 결정한다.

---

## 1. 한 줄 정의

감김(wrap)은 **물리 시뮬레이션의 결과(emergent)** 지만, 감긴 *이후*의 게임플레이는
그 결과를 **`WrapState` 데이터로 고정**하고, 그 데이터 위에서 **유지 / 당김 / 풀림**을 다룬다.
즉 "감기는 동안"은 물리, "감긴 다음"은 **데이터 + 제약(constraint)** 으로 분리한다. (← 퍼포먼스 핵심)

---

## 2. 데이터 모델 — `FRopeWrapState`

감김이 성립한 순간 1회 생성/갱신되는 구조체.

| 필드 | 타입 | 의미 |
|---|---|---|
| `BoneName` | `FName` | 감긴 대상 본 (팔/다리/몸통) |
| `ContactNodes` | `TArray<int32>` | 로프 파티클 중 캡슐과 접촉 중인 인덱스 |
| `WrapTurns` | `float` | 누적 감김 회전수 (접촉점들의 각도 적분) |
| `Tension` | `float` | 현재 장력(0=느슨, 1+=팽팽) |
| `AnchorDistance` | `float` | 끝점~감김 중심 거리 (풀림 판정용) |
| `TimeWrapped` | `float` | 감긴 채 유지된 시간 (포획 성공 판정용) |

> 이 데이터가 곧 게임플레이 API의 입력이다. "어디에/얼마나 강하게/얼마나 오래" 감겼는지를 외부에 노출.

---

## 3. 라이프사이클 상태머신 (퍼포먼스 + "쓸데없는 연산" 대응)

```
 Free ──contact──> Contacting ──turns>=1──> Wrapped ──release cond──> Releasing ──> Free
   ^                                                                      |
   └──────────────────────────────────────────────────────────────────┘
```

| 상태 | 충돌 솔브 | 비용 | 설명 |
|---|---|---|---|
| **Free** | OFF | 최저 | 바디 충돌 끔. 단순 verlet만. 안정되면 sleep |
| **Contacting** | ON | 중 | 캡슐 접촉 감지~감김 성립 판정 |
| **Wrapped** | 감소(접촉 노드만) | 저~중 | 접촉 노드만 제약 유지, 비접촉 구간은 verlet |
| **Releasing** | OFF(점진) | 저 | 제약을 프레임당 풀어주며 Free로 |

→ **"풀 때 쓸데없는 연산"** 은 `Releasing/Free`에서 충돌 솔브를 끄는 것으로 해결.
→ 비접촉 구간은 절대 캡슐 충돌 돌리지 않음(접촉 노드 broad-phase로 한정).

---

## 4. 감긴 이후 3대 동작

### 4.1 유지 (Hold)
- `Wrapped` 동안 접촉 노드를 캡슐 표면 제약으로 유지.
- 본 애니메이션으로 캡슐이 움직이면 접촉점도 따라감(상대 좌표 보정).
- 안정 시 솔버 반복수 ↓ (LOD).

### 4.2 당김 (Pull)  ← 기획서 빈칸의 핵심
- 입력: 로프 **끝점(자유단)** 을 이동/견인.
- 전파: 끝점 이동 → 거리 제약을 따라 장력 상승 → **감김 접촉점이 캐릭터(본/루트)에 힘을 전달**.
- PoC 범위: 캡슐(또는 캐릭터)에 **단순 힘/임펄스** 전달까지만. 풀바디 래그돌 견인은 후속.
- 게임 효과 예시(데이터→게임): 팔 감김+장력↑ → 공격 불가 / 다리 감김 → 이동속도↓ / 일정 시간↑ → 포획 성공.

### 4.3 풀림 (Release)
초기 PoC는 **단순 조건만**, 후속에서 힘/입력 기반 추가:
- 거리 기반: `AnchorDistance > AutoUnwrapDistance` (Settings 값) → `Releasing`
- 명시 호출: `URopeWindingComponent::ReleaseWrap()`
- (후속) 장력 임계 초과 / 특정 입력

---

## 5. 게임플레이 훅 (이벤트)

- `OnWrapped(BoneName)` — 감김 성립
- `OnWrapTensionChanged(Tension)` — 장력 변화
- `OnReleased(BoneName, Reason)` — 풀림
- `OnCaptured(BoneName)` — `TimeWrapped` 임계 초과(포획 성공)

---

## 6. PoC가 **검증**할 것 vs **미루는** 것

| 검증 (S0~S3) | 미룸 (후속) |
|---|---|
| 일자 로프 구조/렌더 | 폐루프 로프 |
| 캡슐 충돌·감김 성립 | 풀바디 래그돌 견인 |
| 움직이는 팔 유지 | 네트워크 동기화 |
| 단순 당김 힘 전달 | 멀티 본 동시 감김 정합 |
| 거리/명시 풀림 | 힘/입력 기반 풀림 |

---

## 7. S2 GO / NO-GO 기준 (이 문서의 결론)

스파이크 S2 = **애니메이트되는 단일 캡슐(팔 스윙)** 에 일자 로프를 감았을 때:

- 🟢 **GO**: 캡슐이 움직여도 (a) 감김이 **N초 이상 유지**되고 (b) **관통/순간이동 없이** (c) 게임 카메라 거리에서 **그럴듯**하며 (d) 목표 예산(예: 로프 1개 < 0.3ms CPU) 내.
- 🟡 **HYBRID**: 유지·예산은 OK지만 비주얼이 싸 보임 → 연출 포즈 블렌딩 병행 검토.
- 🔴 **RESCOPE**: 불안정/관통/예산 초과 → 제한 시나리오 또는 연출 중심으로 재범위화.

> 정량 기준(N초, ms)은 S0에서 실제 측정 가능해지면 확정한다.
